
## Topic 1.8: Types of Database Users

**Goal**: Understand the different people who interact with a database system, what responsibilities they have, and how they differ from one another.


### 1. Who are database users?

Database users are people who interact with a database system, either directly or indirectly, to access, manage, design, or develop database-related applications.

Not everyone interacts with a database in the same way.

For example, consider an online shopping application:

- A customer uses the website to purchase products.
    
- A manager checks sales reports.
    
- A developer writes code that communicates with the database.
    
- A database designer plans how products, customers, and orders should be stored.
    
- A DBA manages database security, backups, and performance.

All these people interact with the database system in different capacities.

There are several classifications of database users. Let's understand them one by one.


### 2. Types of database users

We can broadly divide database users into two groups:

1. **End Users:** People who use database applications to access or work with data.
    
2. **Database Professionals:** People who design, develop, administer, or maintain database systems.

#### A. End Users

End users interact with a database through an application or database tool. They don't necessarily need to understand how the database works internally.

There are four commonly discussed types of end users.

1. **Naive or Parametric End Users**

These users perform predefined, repetitive operations using an application. They generally don't write SQL queries or interact directly with the database.

Examples:

- A bank teller processing a cash withdrawal.
    
- A railway reservation clerk booking tickets.
    
- A student checking examination results.
    
- A cashier processing a purchase.

**How they interact with the database:**

A bank teller enters an account number and withdrawal amount into a banking application. The application sends the appropriate request to the database.

The teller doesn't need to know the SQL query or how the database stores the account information.

**Key point:** They use predefined forms and operations.

2. **Casual End Users**

These users access the database occasionally and perform different queries depending on their requirements.

Unlike parametric users, their operations aren't restricted to predefined, repetitive tasks.

Examples:

- A college principal checking student performance.
    
- A sales manager checking monthly revenue.
    
- A department head reviewing employee records.

How they interact with the database:

A sales manager might request:

- Total sales during October.
    
- Best-selling products.
    
- Revenue generated by a particular region.

These requirements can change depending on what information they need.

**Key point:** They access databases occasionally and perform ad hoc queries or request reports.

3. **Sophisticated or Power Users**

These users have advanced knowledge of databases and use database tools or query languages to perform complex operations and analysis.

Examples:

- Data analysts.
    
- Database researchers.
    
- Engineers working with large datasets.
    
- Business intelligence specialists.

**How they interact with the database:**

A data analyst might write SQL queries involving:

- Multiple table joins.
    
- Aggregation functions.
    
- Subqueries.
    
- Complex filtering and analysis.

For example, an analyst might identify which customer segments generate the highest revenue.

**Key point:** They understand database tools and can perform complex data operations independently.

4. **Standalone Users**

These users manage their own databases using ready-made database software or packages.

They generally don't need to develop a complete database application themselves.

Examples:

- A small business owner maintaining inventory using Microsoft Access.
    
- An individual maintaining personal records in a desktop database.

**Key point:** They use standalone database packages to create and manage their own databases.


#### B. Database Professionals

These people work on creating, designing, developing, and maintaining database systems.

5. **Application Programmers / Developers**

Application programmers develop software applications that interact with databases.

Their job is to write code that allows applications to store, retrieve, update, and delete data.

Examples:

- Backend developers.
    
- Full-stack developers.
    
- Software engineers working on database-driven applications.

Practical example:

Imagine you're developing an e-commerce application using the MERN stack.

A user registers on your website. Your backend receives the registration request and communicates with the database to store the user's information.

Your responsibilities might include:

- Writing backend APIs.
    
- Connecting the application to the database.
    
- Writing SQL queries or using an ORM.
    
- Handling database operations.
    
- Implementing application-level validation and authorization.

**Key point:** Application programmers build software that interacts with databases.

6. **Database Designers**

Database designers are responsible for designing the structure and organization of a database according to application requirements.

Their responsibilities include:

- Identifying what data needs to be stored.
    
- Designing tables and columns.
    
- Defining relationships between tables.
    
- Choosing primary keys and foreign keys.
    
- Defining constraints.
    
- Designing an efficient database schema.

Example:

Suppose you're designing a college database.

You identify the following entities:

- Students
    
- Teachers
    
- Courses
    
- Departments
    
- Enrollments

You then determine how these entities relate to one another and design the appropriate tables and relationships.

**Key point:** Database designers decide how data should be structured and organized.

7. **Database Administrators (DBAs)**

A Database Administrator is responsible for managing and maintaining the database system.

Their responsibilities include:

- Managing database security and user permissions.
    
- Performing backups and recovery.
    
- Monitoring database performance.
    
- Managing database availability.
    
- Handling database configuration and maintenance.
    
- Monitoring storage and resource usage.

Example:

Suppose an e-commerce application has millions of users.

The DBA ensures that:

- Unauthorized people cannot access sensitive data.
    
- Backups are performed regularly.
    
- The database remains available.
    
- Database performance is monitored and optimized.
    
- Data can be recovered after a failure.

**Key point**: DBAs manage, maintain, secure, and monitor database systems.

We'll study the DBA's responsibilities in detail in Topic 1.9.


### 3. Complete comparison of database users

|Type|Main responsibility|Example|
|---|---|---|
|Naive / Parametric|Perform predefined operations|Bank teller|
|Casual|Access data occasionally|Sales manager|
|Sophisticated / Power|Perform complex queries and analysis|Data analyst|
|Standalone|Manage personal databases using ready-made software|Small business owner|
|Application Programmer|Develop database-driven applications|Backend developer|
|Database Designer|Design database structure|Database architect|
|DBA|Administer and maintain databases|Database administrator|

**Note:** Different textbooks may classify these roles slightly differently. The four end-user categories are a common textbook classification.

### 4. How these roles work together in a real application

Let's take an e-commerce application as an example.

## E-commerce database system

			   End Users
	Customers, managers, support staff
	 Use the application to interact with data

		Application / Backend
    Developed by application programmers
Processes requests and communicates with the database

				Database
	   PostgreSQL / MySQL / MongoDB
	Stores and manages application data

Notice something important: a database user doesn't necessarily interact with the database directly.

A customer uses the frontend, the backend communicates with the database, and the database processes the request.

### 5. Quick revision

- **Naive/Parametric:** Uses predefined operations.
    
- **Casual:** Performs occasional, changing queries.
    
- **Sophisticated/Power**: Performs complex queries and analysis.
    
- **Standalone:** Manages personal databases using ready-made software.
    
- **Application Programmer:** Builds applications that communicate with databases.
    
- **Database Designer:** Designs database structure and relationships.
    
- **DBA:** Manages and maintains the database system.
